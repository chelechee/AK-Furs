# AK Furs — расчёт ответов по тестовому заданию

Одна команда пересчитывает `answers.json` из четырёх сырых выгрузок: CRM, банковской выписки, справочника цен и 150 переписок. Числовой тракт детерминированный, без обращений к LLM.

## Запуск

```
pip install -r requirements.txt
python solve.py data/ --out answers.json
```

Каталог `data/` содержит четыре исходных файла. Проверено на чистой копии проекта: команда работает без правок.

> В Windows PowerShell 5.1 перенаправление `>` перекодирует вывод в UTF-16, и файл перестаёт читаться как UTF-8. Поэтому используется флаг `--out`: он пишет UTF-8 без BOM. В bash и cmd эквивалентная запись `python solve.py data/ > answers.json` работает корректно.

## Ключевые решения

Полный текст — в поле `notes` файла `answers.json`. Кратко:

- Номер заказа приводится к целому: `A-00075`, `А-75`, `a-75`, `A75` → 75.
- Строки дедуплицируются по паре «номер + № строки», побеждает максимальное «Выгружено»; ничьи разрешаются порядком строки в файле.
- Статус определяется только полем «Статус»; комментарий о возврате его не меняет.
- Порядок `ДД/ММ/ГГГГ` — день первым. Проверено тремя способами: при обратном порядке 138 дат не разбираются, 21 платёж оказывается раньше своего заказа, и расходятся даты внутри 32 заказов.
- Цена: если в числе есть и точка, и запятая, десятичным считается правый разделитель (`17,000.00` → 17 000, `50.000,00` → 50 000); если только запятая — она десятичная, кроме вида `1,234` с группами по три цифры. Суффикс «млн» умножает на миллион.
- Переименования артикулов применяются безусловно: старый код встречается и после даты перехода.
- Платёж привязывается к заказу только при наличии номера существующего заказа; телефоны и даты из назначения вычищаются, номера вне диапазона CRM считаются неопознанными.
- Q2a: заказ считается оплаченным, если «Оплачен» хотя бы одна его строка; после дедупликации смешанных статусов внутри заказа не остаётся, поэтому на текущих данных правило на ответ не влияет.
- Q3: исключены только строки «Отменён», «Возврат» входит. В разбивке перечислены только менеджеры с нарушениями.
- Q4: учитываются только реплики менеджера; ценой считается сумма в любой записи, включая прописью и без указания валюты; чат, где цена не названа вообще, считается нарушением.

## Проверки

- `python -m pytest tests -q` — 113 тестов: форматы, дедупликация, границы периодов, извлечение номеров, классификация реплик, стресс-наборы.
- Детерминизм: два прогона дают идентичный файл (сверка по хешу).
- Прогон на чистой копии проекта даёт тот же результат.
- Инварианты в тестах: ни один платёж не раньше своего заказа; каждая строка находит период прайса; разбивка по менеджерам суммируется в общий итог.

## Ограничения

- Разметка чатов опирается на шаблоны реплик, встречающиеся в текущей выборке. Незнакомый формат даты, цены или статуса приводит к исключению с понятным сообщением, а не к молчаливому пропуску.
- Если в новой версии данных платёж будет содержать два разных существующих номера заказа, программа остановится с ошибкой неоднозначности: правило приоритета в ТЗ не задано.
- `q3_price_violation_lines_by_manager` содержит только менеджеров с нарушениями; нулевые значения не добавляются.

## Состояние

- Все пять вопросов считаются одной командой, ответы детерминированы, схема проверяется валидатором перед выводом.
- Сырые данные в репозиторий не включены: каталог `data/` перечислен в `.gitignore`.
- Стресс-наборы воспроизводятся командой `python tools/stress.py data stress`.
